OpenControl Protocol Library реализует исследованный сетевой протокол OpenControl:
управляющие сообщения, зашифрованные UDP-пакеты, переходы состояний и обновления
маршрутов. Библиотека предоставляет общий протокольный слой для приложений
с собственным транспортом и интеграцией с операционной системой.

**Текущая версия:** `0.9.0` · **Crate:** `opencontrol-protocol` · **Версии протокола:** `1–4`

## Возможности

| Область | Что предоставляет библиотека |
|---|---|
| **Управляющий канал** | Инкрементальный разбор кадров, типизированные сообщения, ограничения ресурсов и сохранение неизвестных данных. |
| **Жизненный цикл** | Автоматы клиентского, серверного и S2S-профилей, два ключевых слота, защита от устаревших событий, таймауты и отмена. |
| **Канал данных** | AES-128-GCM, форматы UDP-пакетов и защита от повторов отдельно для каждого слота и поколения ключа. |
| **Обновления маршрутов** | Повторные, пустые и многочастные ROUTES, маршруты полного туннеля и отдельный статус safeLan. |
| **Интеграция с платформой** | Разделение желаемого и применённого состояния, подтверждение операций, повторные попытки и учёт владельцев ресурсов. |
| **Legacy-совместимость** | Опциональный Blowfish в счётчиковом формате с явным включением при сборке и во время работы. |

Ядро синхронное и не требует асинхронной среды выполнения. Сокеты, проверка
TLS-сертификатов, TUN/TAP, DNS, системные маршруты и firewall остаются приложению.

## Подключение

Добавьте Git-зависимость в `Cargo.toml` приложения:

```toml
[dependencies]
opencontrol-protocol = { git = "https://github.com/nr084/opencontrol-protocol.git", tag = "v0.9.0", version = "=0.9.0" }
```

Библиотека распространяется через GitHub; публикации в crates.io нет.
Сохраняйте `Cargo.lock` приложения для воспроизводимого выбора зависимостей.
Для разработки используется последний stable Rust; заявленный минимум — Rust 1.99.

### Обработка повторных маршрутов

Храните один `RouteState` на протяжении всего соединения. Периодическое сообщение
может быть корректным и при этом не менять эффективную конфигурацию:

```rust
use opencontrol_protocol::{ProtocolError, ProtocolLimits, RouteState, RouteUpdate, Routes};

fn main() -> Result<(), ProtocolError> {
    let mut routes = RouteState::new(ProtocolLimits::default());
    let update = Routes { flags: 3, records: vec![] };

    assert!(matches!(routes.apply(&update)?, RouteUpdate::Changed(_)));
    assert!(matches!(routes.apply(&update)?, RouteUpdate::Unchanged(_)));
    Ok(())
}
```

`Unchanged` — успешный результат обработки: сохраняйте соединение, ключи
и VPN-интерфейс. Однако он не подтверждает успех предыдущих операций ОС.
`RouteApplications` позволяет учитывать фактически применённые операции
и повторять неудачные, в том числе после сообщения без изменений.
Многочастный список START/END применяется к ОС после получения END.

Запустите пример с имитацией платформенного слоя:

```sh
cargo run --example client_routes
```

**Обновляете существующий клиент?** Замените обработчик, который считает очередной
ROUTES причиной завершить соединение. Одно обновление зависимости его не исправит.
См. [руководство по миграции](MIGRATION.md), включая обязательные изменения Android.

## Варианты интеграции

- **Координация сессии:** `ProtocolSession` объединяет состояние, ключи, привязку
  endpoint, маршруты и таймауты. Транспортом продолжает управлять приложение.
- **Отдельные компоненты:** используйте кодеки, `RouteState`, `DataCipher` или
  `KeySlots`, если приложение уже координирует остальные части соединения.
- **Site-to-Site:** отдельные профили инициатора и принимающей стороны
  с клиентским сертификатом. Сертификаты проверяет и роль выбирает транспорт.
- **Legacy:** требуются Cargo feature `legacy` и runtime-настройка
  `LegacyPolicy::ExplicitlyEnabled`. Автоматического перехода на legacy нет.

Подробнее: [архитектура](ARCHITECTURE.md), [S2S](S2S.md), [legacy-совместимость](LEGACY.md).

## Проверки и совместимость

Версия 0.9.0 прошла **50 автоматических тестов, включая doctests**, проверки
качества на stable Rust и четыре коротких Linux nightly fuzz-прогона с санитайзером.
Реальное клиентское соединение работало **21 минуту** и пережило два периодических
ROUTES и одну смену ключа без переподключения. Также проверены обе роли S2S
и явно включённый legacy. Точные результаты и границы проверки —
в [отчёте](VALIDATION.md).

API находится на стадии до 1.0. Версии библиотеки, продукта, сетевого протокола
и TLS — отдельные понятия. Legacy checksum не обеспечивает криптографическую
аутентификацию. safeLan — статус, а не команда блокировать локальную сеть.
IPv6-пакет можно представить в формате канала данных; согласование IPv6-адресов,
маршрутов и сквозная совместимость не установлены. Поддержка всех версий продуктов,
бесшовная NAT-миграция и неограниченное время совместной работы ключей не заявлены.
См. [свойства безопасности](SECURITY.md).

## Разработка

```sh
cargo fmt --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-targets --all-features --locked
cargo test --workspace --doc --all-features --locked
cargo doc --workspace --no-deps --all-features --locked
```

CI также проверяет сборку с default features и выполняет Linux nightly fuzz smoke.
Изменения протокола должны опираться на доказательства и синтетический либо
обезличенный регрессионный тест. Не добавляйте реквизиты, ключи сессии и приватные
захваты трафика в issues, fixtures или fuzz-корпусы.
